# データ設計

> **2026-10-16 注記:** 本書は実装前の設計案。現行の型は次のとおりで、本文中の `PlayerStatus`／`Dictionary` 型の好感度・熟練度／`PlayerBikeState.ComponentPartId`／`BikePartMaster`／`Weight`・`Damping` は採用していない。
> - 能力: `GamePlayerData` 直下の `Physical`／`Toughness`／`Smart`／`Empathy`／`Appeal`
> - 好感度・ルート: `List<HeroineProgress>`（`Affection`／`RouteStep`／`IsMet`／`IsUnlocked`）
> - 機材: `OwnedPartIds`、`EquippedBike`（`PlayerBikeEquipment`: `FramePartId`／`ComponentsPartId`／`WheelPartId`）、`List<BikeMasteryProgress>`
> - パーツ定義: `BikePartDefinition`（`Id`／`Name`／`Slot`／`Price`／5性能値／`Tags`）。性能は `Stiffness`／`Lightness`／`Comfort`／`Handling`／`Aerodynamics`
> - 定義データはScriptableObjectではなく `Assets/Resources/Content/*.json`。編集方法は [22_外部データの編集ガイド.md](../運用/22_外部データの編集ガイド.md)、名称の正本は [11_用語統一メモ.md](../企画/11_用語統一メモ.md)。

この文書は、現在の Unity コード構造を前提に、実装しやすいデータ設計案をまとめたものです。

## 設計方針

- セーブ対象とマスタデータを分離する
- 実行時に変わる値は `GamePlayerData` 側へ置く
- 調整対象は ScriptableObject またはマスタデータへ寄せる
- イベントは参照キー中心でつなぐ

## スケジュールデータ

今の `ScheduleDay` は、日付の基本情報と時間帯ごとの `ScheduleSlot` を持つ形へ寄せるのが扱いやすい。

```csharp
[Serializable]
public class ScheduleDay
{
    public int Year;
    public int Month;
    public int Day;
    public Weather Weather;
    public DayOfWeek CurrentDay;
    public Season Season;
    public bool IsHoliday;
    public bool IsSpecialDay;
    public List<ScheduleSlot> Slots;
}
```

時間帯スロットは以下のように持つ。

```csharp
[Serializable]
public class ScheduleSlot
{
    public ActionTiming Timing;
    public ScheduleSlotType SlotType;
    public string FixedEventKey;
    public List<string> CandidateEventKeys;
    public string FallbackEventKey;
}
```

役割:

- `ScheduleDay`
  - 日付の土台
  - 曜日、天気、休日、季節の定義
- `ScheduleSlot`
  - その時間帯に何系のイベントを引くかの定義
  - 固定イベントか、候補選択かの管理

`Morning` は固定イベント、`Afternoon` は自由行動候補、`Evening` はまとめ、`Special` は休日イベントやレース、といった分け方を基本にする。

## 依存関係の基本形

1. 日付と時間帯からイベントキーを引く
2. イベントキーからイベント定義を引く
3. イベント定義からシナリオや行動内容を引く
4. 終了時に報酬を適用する
5. セーブデータへ反映する

## Timing の扱い

- `Timing` は `int` ではなく `ActionTiming` を正式型として扱う
- 保存データもゲーム概念に合わせて enum ベースで持つ
- `Morning / Afternoon / Evening / Special` がそのまま進行状態になる

## イベント ID ルール

- 日付と時間帯が分かる prefix を持たせる
- 末尾は連番で振る

例:

- `evt_2026_04_01_morning_001`
- `evt_2026_04_03_afternoon_001`
- `evt_2026_04_05_special_001`
