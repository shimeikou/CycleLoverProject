# 開発の進め方

この文書は、今の Unity プロジェクトを破綻させずに、段階的にゲームとして成立させていくための進め方をまとめたものです。

更新日: 2026-10-14

3日間の試作はEditorで検証済み。作業状態は [17_実行用タスク一覧.md](../運用/17_実行用タスク一覧.md)、検証記録は [19_3日間試作の実装と検証.md](19_3日間試作の実装と検証.md) を参照。

## 基本方針

- 一気に全機能を作らない
- まずは 1 本の細いプレイ体験を最後まで通す
- データ仕様を先に決め、画面や演出は後から厚くする
- UI より先に進行ロジックを安定させる

## おすすめの進め方

### 1. 企画用語を固定する

先に固定したいもの:

- ステータス名称
- 時間帯名称
- ルート解放条件の呼び方
- 機材カテゴリ名
- イベント種別名

これを先に決める理由:

- コード、ScriptableObject、UI 文言のズレを防ぎやすい

### 2. 最小ループを先に完成させる

最初に成立させたいプレイ体験:

1. タイトル開始
2. 初回導入イベント
3. 午後行動を選ぶ
4. 夜に結果確認
5. 翌日に進む
6. 数日後にヒロインイベントが起きる

現状の補足:

- 入口は `InitScene` の Start ボタン起点を正式採用する
- 直開きデバッグ導線は必須にしない
- 最小ループの検証も `InitScene -> Start -> MainGameScene` 前提で行う

この段階では不要なもの:

- 全ヒロイン
- 本格レース
- 全ブランド
- 高度な UI 演出

### 3. 1 ルートで縦切り検証する

最初の 1 ルートで確認したいこと:

- 会話イベントが気持ちよく読めるか
- ステータス条件が分かりやすいか
- 行動選択に意味があるか
- 1 週間から 1 か月分の進行が退屈でないか

### 4. データ主導に寄せる

できるだけコードにハードコードしない方が良い項目:

- 日付ごとのイベント
- 好感度条件
- ステータス条件
- 購入価格
- パーツ性能
- レース難度

メリット:

- 後から調整しやすい
- シナリオ追加が楽になる
- バランス調整のコストが下がる

## 実装のレイヤー分け

### レイヤー 1 コアモデル

- 日付
- プレイヤー状態
- バイク状態
- 好感度
- 資金

### レイヤー 2 進行制御

- イベント引き当て
- 時間進行
- 条件判定
- 分岐管理

### レイヤー 3 表示

- UI 表示
- シナリオ表示
- ステータス表示
- 選択肢表示

### レイヤー 4 コンテンツ

- ヒロインイベント
- 地域イベント
- ショップ
- レース

## 開発サイクル

おすすめの 1 サイクル:

1. 小さな仕様を 1 つ決める
2. データ構造を決める
3. 最小実装を入れる
4. ダミーデータで動かす
5. UI に出す
6. 触って違和感を直す

## 実装時の注意

### スケジュール依存を強くしすぎない

- 全イベントを日付固定にすると運用が重くなる
- 条件型イベントと日付固定イベントを分けると扱いやすい

### ルート分岐を早く複雑にしすぎない

- 最初は排他ルートにしすぎない
- 序盤は複数ヒロインと自然に関われる方が検証しやすい

### レースを重くしすぎない

- まずは簡易シミュレーションで良い
- 面白さの核がシナリオなら、先にそちらを成立させる

## 当初の2段階計画（期間の確約なし）

### 第1段階

- 用語統一
- `GamePlayerData` の整理
- 進行管理の整理
- イベント再生の最小化
- 3 日から 7 日のダミーデータ作成

進捗:

- 用語統一: 実施済み
- 進行管理の整理: 3日間試作として実装・検証済み。本編基盤への統合は残る
- 3 日ダミーデータ: 実施済み
- イベント再生の最小化: 画面の本文表示・ページ送りを実装済み
- UI 接続: 行動選択・本文・日次結果・保存・タイトルを接続済み
- セーブロード: 実ファイルとPlay再開後の復帰を確認。アプリ再起動は未検証

### 第2段階

- ヒロイン 1 名の導入から進展まで実装
- 好感度と条件分岐
- 行動 UI
- セーブロードの実地確認

## 実装担当が 1 人でも回しやすい順番

- 仕様確定
- データ構造定義
- ダミーデータ作成
- ロジック実装
- UI 接続
- シナリオ投入
- 調整

## 次にやること

1. 試作の行動定義と本文をデータ化し、イベント基盤に接続する（T03・T04）。
2. 配布用ビルドで操作・終了・再起動・ロードを確認する（T07・T08）。
3. 1ヒロインの短期ルートを定義する（T09）。
4. 好感度、条件分岐、本文、背景・人物表示を追加する（T10〜T13）。
5. 成功／条件未達の結末まで通し検証する（T14）。
