# スケジュールデータ設計

この文書は、`ScheduleDay` を中心にした日付進行データの完成イメージをまとめたものです。

## 基本方針

- 日付データは薄く持つ
- イベント本体は `GameEvent` 側へ寄せる
- スケジュールは「この時間帯で何を引くか」を持つ
- 固定イベントと候補イベントを分ける

## レイヤー構成

### 1. Calendar

日付そのものの情報を持つ。

- 年
- 月
- 日
- 曜日
- 季節
- 天気
- 祝日
- 特別日

### 2. ScheduleSlot

各時間帯のイベント枠を持つ。

- `Morning`
- `Afternoon`
- `Evening`
- `Special`

### 3. EventResolver

時間帯枠とプレイヤー状態から、最終的に発火するイベントを決める。

- 好感度
- ステータス
- 天気
- 休日
- 進行フラグ
- ルート状況

## クラス構成

### ScheduleDay

```csharp
[Serializable]
public class ScheduleDay
{
    public int Year;
    public int Month;
    public int Day;
    public Weather Weather;
    public DayOfWeek CurrentDay;
    public Season Season;
    public bool IsHoliday;
    public bool IsSpecialDay;
    public List<ScheduleSlot> Slots;
}
```

### ScheduleSlot

```csharp
[Serializable]
public class ScheduleSlot
{
    public ActionTiming Timing;
    public ScheduleSlotType SlotType;
    public string FixedEventKey;
    public List<string> CandidateEventKeys;
    public string FallbackEventKey;
}
```

### ScheduleSlotType

```csharp
public enum ScheduleSlotType
{
    FixedEvent,
    FreeChoice,
    ConditionalEvent,
    Summary,
    SpecialEvent,
}
```

## スロットの使い分け

### Morning

- 基本は仕事固定
- 例: `work_basic`

### Afternoon

- 自由行動の主枠
- 候補イベントを持つ
- 例:
  - `free_training`
  - `free_talk_cafe`
  - `free_shop`

### Evening

- 1 日のまとめ
- ステータス確認
- 短い会話イベント
- 例: `daily_summary`

### Special

- 休日イベント
- レース
- デート
- 条件付き長尺イベント

## 設計上のポイント

### 固定イベントを書きすぎない

- すべての日付を完全固定にすると運用が重い
- 固定にするのは導入や重要イベントだけにする

### 候補イベント方式を使う

- 午後などは候補キーを複数持たせる
- 実際の選択や条件判定はイベント解決側で行う

### Fallback を持つ

- 条件を満たさなかった場合に空振りしない
- 例: `free_rest_default`

## 1 日のサンプル

```text
2026-04-03 Fri
Morning: work_basic
Afternoon: free_training / free_talk_cafe / free_shop
Evening: daily_summary
Special: なし
```

## 休日のサンプル

```text
2026-04-05 Sun
Morning: work_optional_rest
Afternoon: free_long_ride / free_visit_bikeshop
Evening: daily_summary
Special: event_cafe_date_001
```

## 直近の実装ステップ

1. `ScheduleDay` を今の形で固定する
2. `ScheduleSlot` を使う前提で `GameEvent` 側の必要項目を整理する
3. 1 週間分のサンプル日程を表で作る
4. その中の 3 日分だけ実データ化する

## 現在のサンプル方針

- イベント ID は `evt_YYYY_MM_DD_timing_連番`
- 最初の 3 日は以下を扱う
  - 主人公の現在地説明
  - 祖母との暮らしの導入
  - 古いロードバイクの発見
  - ヒロイン 1 との出会い
