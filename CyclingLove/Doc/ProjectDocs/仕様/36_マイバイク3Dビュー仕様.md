# マイバイク3Dビュー仕様

更新日: 2026-10-20

## 目的と範囲

マイバイク／装備画面では、現在装着中または選択中の自転車を3Dで確認できるようにする。

- 対象: マイバイク、装備変更、ショップでの装備プレビュー
- 対象外: 街中移動の3D化、走行物理、自由探索、3Dキャラクター
- 初回macOS版では「見て選ぶ」機能を完成条件とする
- 将来のスマートフォン版でも同じモデルと装備データを利用できる構成にする

3D表示はゲーム進行から独立した表示機能とし、セーブデータや年間進行の責務を持たせない。

## 画面構成

`MainGameScene` のマイバイク画面内に `RawImage` を置き、専用カメラが描画した `RenderTexture` を表示する。

- 画面遷移を伴う専用シーンは作らない
- 初期実装は `BikePreviewController` が `BikePreviewRig` 相当を必要時だけ生成し、画面を閉じたら破棄する。本番素材投入時にプレハブへ置換してよい
- プレビュー用オブジェクトは専用Layerに置き、通常カメラには映さない
- 背景、照明、床影、カメラをリグ内に閉じ込める
- モデル読込中も装備画面のテキスト操作は止めない

現在の `MainScenePresenter` と装備サービスを保ったまま、3D表示だけを追加する。

## 操作

| 操作 | macOS | 将来のスマートフォン |
| --- | --- | --- |
| 回転 | 左ドラッグ | 1本指ドラッグ |
| 拡大縮小 | ホイール／トラックパッド | ピンチ |
| 初期位置へ戻す | リセットボタン | リセットボタン |
| 部品確認 | 装備候補選択で即時プレビュー | 同左 |
| 装備確定 | 「装備する」で保存 | 同左 |

候補を表示しただけでは `PlayerBikeEquipment` を変更しない。装備確定後にだけ現在装備へ反映する。

## コード責務

### Domain

既存の `PlayerBikeEquipment` と `BikePartSlots` を正とする。DomainにはUnityのプレハブ、マテリアル、Addressables参照を持ち込まない。

### Application / Presentation

- `BikePreviewLoadout`: 表示対象のFrame、Components、WheelsのIDを保持
- `BikeVisualCatalog`: 部品IDから配信用アドレスを解決
- `BikePreviewController`: モデルの非同期読込、差し替え、キャンセル、解放
- `BikePreviewInput`: 回転、ズーム、リセット操作
- `BikePreviewRig`: カメラ、照明、組立先、背景のUnity表現

装備候補の変更通知を `MainScenePresenter` から `BikePreviewController` へ渡す。3D読込に失敗しても、購入、装備確定、年間進行は継続可能にする。

## 表示カタログ

ゲーム内の部品定義 `BikeParts.json` と3D素材を分離し、表示側のカタログで結ぶ。

```json
{
  "Version": 1,
  "Parts": [
    {
      "PartId": "frame_musashi_touring_01",
      "Slot": "frame",
      "Address": "bike/part/frame_musashi_touring_01",
      "FallbackAddress": "bike/fallback/frame",
      "PackId": "initial_bike_visuals"
    }
  ]
}
```

- `PartId` は `BikeParts.json` と完全一致させる
- `Slot` は `frame`、`components`、`wheels` のいずれか
- `Address` はカタログ差し替えや暗号化後も変えない論理アドレスとする
- 素材未配信、破損、非対応端末では `FallbackAddress` を表示する
- `PackId` で初回必須と必要時取得を判別する
- セーブデータにはアドレスを保存せず、部品IDだけを保存する

## 3Dプレハブ規約

### 共通座標

- 1 Unity unit = 1m
- Y-up、Z-forward、X-right
- Transform scaleは `(1, 1, 1)`
- フレーム原点はボトムブラケット中心
- 標準ホイール半径は0.34mを基準とする

### フレーム

フレームプレハブは `Mount_Components`、`Mount_WheelFront`、`Mount_WheelRear` を持つ。フレームごとのホイールベース差は各アンカー位置で吸収する。

### コンポーネント

初回版では駆動系、クランク、ディレイラー等を1プレハブとして扱う。部品スロット自体が増えた段階で細分化する。

### ホイール

前後輪を1商品・1スロットとして扱うため、ホイールプレハブは `Front` と `Rear` の2子要素を持つ。組立時に各フレームの前後アンカーへ配置する。

## 素材仕様

| 対象 | 推奨上限 |
| --- | --- |
| 完成車 LOD0 | 80,000 triangles |
| 完成車 LOD1 | 35,000 triangles |
| 完成車 LOD2 | 10,000 triangles |
| 同時マテリアル数 | 6 |
| フレーム主要テクスチャ | 2048×2048 |
| 小部品テクスチャ | 1024×1024 |
| プレビュー描画 | 1024×1024 RenderTexture |

入力形式と命名:

- モデル: `<part_id>_mesh.fbx`
- プレハブ: `<part_id>.prefab`
- Base Color: `<part_id>_basecolor.png`（sRGB）
- Normal: `<part_id>_normal.png`（Normal Map）
- Mask: `<part_id>_mask.png`（Linear）
- 制作元データはUnity配布物から分離して保管する

配置先:

```text
Assets/Content/External/Initial/Models/Bikes/Parts/<part_id>/
Assets/Content/External/OnDemand/Models/Bikes/Parts/<part_id>/
Assets/Content/BuiltIn/Prefabs/BikePreview/
```

## 配布区分

### builtin_core

- `BikePreviewRig`
- プレビュー用シェーダーと共通マテリアル
- 各スロットの軽量フォールバックモデル
- 読込失敗表示

### initial_bike_visuals

新規ゲーム開始時の標準装備3点を含める。初回必須ダウンロード完了後は、必ず完成車を表示できる状態にする。

### bike_parts_visuals

標準装備以外の部品モデルを格納する。ショップ表示または入手時にカタログとキャッシュを確認し、必要なバンドルだけ取得する。

部品IDと論理アドレスは固定し、将来ZIP初期配布、Addressablesカタログ更新、暗号化保存を追加してもセーブデータを変更しない。

## 読込と破棄

1. 装備画面を開いたら現在装備の3部品を解決する
2. ローカルキャッシュを確認する
3. 不足素材は配信状態を表示し、フォールバックで画面を成立させる
4. 読込完了ごとに該当スロットだけ差し替える
5. 別候補を選択したら古い要求をキャンセルする
6. 差し替え済みアセットの参照を解放する
7. 画面を閉じたらリグ、RenderTexture、Addressablesハンドルを解放する

非同期処理には世代番号またはCancellationTokenを使用し、遅れて完了した古い候補が最新表示を上書きしないようにする。

## 現在の実装状態

2026-10-20時点では、素材待ちでも画面と操作を検証できる仮ポリゴン版まで実装済み。

- 3スロットのIDからフレーム形状、色、ホイールリム幅、コンポーネント形状を変えて1台を組み立てる
- 専用カメラ、照明、床、1024×1024 RenderTextureを実行時生成する
- 現在装備を表示し、ショップ／装備候補へポインターを合わせると一時プレビューする
- 自転車メニューは午後の行動選択中だけ利用する。ショップ・装備・レースを確認した後に通常の日次行動を選び、本文や日次結果の途中には割り込ませない
- 一時プレビューではセーブデータを変更せず、「購入」「装備する」の確定処理を従来どおり使う
- ドラッグ回転、ホイール拡大、ダブルクリック／ボタンの視点リセットに対応する
- 画面を閉じるとプレビュー階層、RenderTexture、実行時Mesh／Materialを破棄する
- 現行8部品は `BikeVisuals.json` と `BikeParts.json` の全件整合を検証する
- Unityと同じRoslyn設定によるC#コンパイルは成功。Editor／Playerでの見た目と操作は未確認

仮形状は `builtin_core` のフォールバック相当として扱う。本番モデルとAddressables取得は未接続で、部品IDと画面側の呼び出しはそのまま差し替えられる。

## 完成条件

- 現在装備3スロットから1台の自転車を組み立てて表示できる
- 8件の既存部品すべてに表示カタログ項目または明示的なフォールバックがある
- 候補選択ではセーブデータが変わらず、装備確定時だけ更新される
- 部品を連続選択しても古い非同期結果が残らない
- 画面を開閉した後にモデルとRenderTextureの参照が残らない
- モデル欠損、配信失敗、カタログ不一致でも進行不能にならない
- macOS 13インチのフルスクリーン表示で輪郭と材質を確認できる
