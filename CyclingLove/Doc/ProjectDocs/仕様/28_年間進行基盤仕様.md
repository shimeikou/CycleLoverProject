# 年間進行基盤仕様

更新日: 2026-10-21

## 目的

T21の最初の実装として、現行10日版を変更せず、1年間の日付・四季・休日・特別枠・季節目標・年末結末を外部データから解決する基盤を追加する。ヒロイン固有イベント、スキップ、周回解放、地域イベントはT21〜T24で接続済み。年間バランスとPlayer実機確認を後続で行う。

## 正本データ

`Assets/Resources/Content/AnnualCalendar.json` を編集用の正本とする。初期定義は2026年4月1日から2027年3月31日までで、春・夏・秋・冬が全日を重複なく覆う。

- `WeekendsAreHolidays`: 土日を休日として扱う。
- `DateOverrides`: 日付単位で休日／平日を上書きし、特別枠IDを0件以上指定する。
- `SeasonGoals`: 季節、締切、条件、成功／未達フラグを定義する。
- `Endings`: 優先度順に条件を評価する。条件なしの未達結末を必須のフォールバックとする。

日本の祝日、季節目標の数値、告白相手の確定条件は企画上の未確定事項なのでコードへ固定しない。現在の `goal_*_ready` と `annual_confession_ready` は、後続ルートが達成時に付与する統合用フラグであり、最終バランス値ではない。

## 検証規則

- 開始日から終了日までがちょうど1年間である。
- 四季は4件で、各日が必ず1つの季節だけに属する。
- 日付例外は期間内かつ重複なし。休日指定は `inherit / holiday / workday` のいずれか。
- 季節目標の締切は対象季節の範囲内に置く。
- 結末IDと優先度は重複不可。条件なしの結末を最低1件置く。
- ビルド前のコンテンツ検証で年間JSONも読み込み、異常時はビルドを中止する。

## 現在の実装範囲

`AnnualCalendarService` は任意の日付について曜日、季節、休日、特別枠、最終日を返す。季節目標は既存の `CampaignCondition` で判定し、成功／未達フラグを返す。年末結末は優先度順に条件を評価する。

`AnnualProgressService` は締切日以降の季節目標と最終日の年末結末をプレイヤー状態へ一度だけ適用する。結果ID、成否、結果フラグ、判定日を保存し、同じ処理を再実行してもフラグとRevisionを重複更新しない。保存形式はv3とし、v1／v2から不足欄を補完する。年間結末は未確定状態を明示して途中保存と区別する。

`CampaignGameService` は年間定義を任意依存として受け取り、各 `GameSceneRequest` へ季節ID・表示名、休日、最終日、特別枠IDを載せる。画面側は日付HUDへ季節、平日／休日、特別日、最終日を併記する。日次結果を閉じる際は日付を進める前に期限到達済みの未確定目標を補完し、最終日には年末結末も確定する。10日版も同じ進行コードを使う。

`AnnualCampaign.json` と `AnnualSchedule.json` は年間版の実行データ。日程側には平日・休日・季節締切・年末とルートイベントのテンプレートを置き、カレンダーの日付、休日、季節、特別枠と優先ルールから起動時に365件の一意な `CampaignDay` を生成する。展開時に各日のNodeIdへ日付IDを付加し、日をまたいだ重複を防ぐ。365日の展開はカレンダーの `StartDate` から、進行の開始日は `AnnualCampaign.json` の `StartYear`／`StartMonth`／`StartDay` から取り、読み込み時に一致を検査する。ルート選択、自転車屋の娘、カフェのマスターの年間行動は別カタログへ分離し、マニフェストの追加アクション参照で通常行動と結合する。

`AnnualSchedule.json` の `ConditionalEvents` は、期間、季節、休日区分、特別枠、既存の `CampaignCondition` と優先度から当日の固定イベントを選ぶ。成立候補が複数ある場合は優先度降順、同値ならID順で1件を選ぶ。選択結果は `ResolvedDayKey`／`ResolvedDayEventId` として保存し、日中に能力やフラグが変わっても翌日まで差し替えない。`Repeatable` がfalseのイベントは、既読キーが残っている限り再発しない。

通常日スキップは `CampaignGameService` と `GameFlowManager` にプレビュー・実行APIを追加した。平日の通常日だけを進め、休日、特別枠、成立済みの未読条件イベント、キャンペーン終端で停止する。スキップ中は仕事・行動・好感度などの日次報酬を付与せず、体力だけ上限へ回復する。年間キャンペーンの午前開始時だけ「日程」ボタンを表示し、最大7日分の停止日・理由・報酬非加算を確認してから実行する。

2026-10-21時点で、上記に加えて条件イベントの優先度・日中固定・保存復元、イベント／休日でのスキップ停止、10日版でのスキップ無効化、開始日不一致の拒否、365日分のNodeId一意性をEditModeテストで確認。年間開始時に通常3名から1ルートを選び、完走記録により隠し2名を追加解放する。5ルートすべてで各8イベントから専用告白結末まで通し検証済み。地域進行値、5ルート別の地域支援、狐の依頼と報酬重複防止、調整画面の条件境界評価も検証済み。現行全体94ケース成功後、年間バランス19ケースと調整画面3ケースを対象実行して成功、コンパイルエラー・警告なし。macOS Universal Playerは133,920,281 bytes、0 errorsで生成し、1280×720ウィンドウで年間版4月1日まで表示確認済み。保存終了・再起動以降は未確認。

## 初回バランス基準

- 5能力の初期値は5、年間ルートの主要能力条件は7とする。通常行動を適切に2回前後選べば準備できる値で、365日の自由行動を阻害しない。
- 各ヒロインの初回イベント本体で好感度1を付与し、2回目以降の好感度は関係を深める会話選択から得る。イベントを見ただけでは告白条件へ到達しない。
- 中盤の関係選択は好感度5、最終告白は好感度7を境界とする。全8イベントの関係選択を積み上げる経路では告白でき、常に無条件の代替選択を選ぶ経路では告白できない。
- 女子アナとネットのライバルも通常3ルートと同じ好感度配分へ統一する。周回解放はルート選択条件だけに影響し、恋愛進行を自動成功させない。
- `Tools/Cycling Love/Campaign Tuning` は採用イベントに加え、各選択肢の選択可否、必要条件、対象ID、現在値／必要値を表示する。実セーブは変更しない。
