# macOS表示・素材制作仕様

更新日: 2026-10-16

## 目的

初回macOS版の表示品質と、立ち絵・背景・CG・UI・音の制作条件を固定する。この文書を素材の発注、生成、受け入れ、Unityインポート、実機確認の共通基準とする。

## 表示ベンチマーク

- 基準実機: MacBook Air 13インチ（M4、2025）。
- 基準表示: 内蔵Liquid Retinaディスプレイ、ネイティブ2560×1664、224ppi。
- 合格判定: macOS Playerを内蔵画面でフルスクリーン実行し、文字・立ち絵・背景・UIがぼけず、不自然な伸張、重要部分の見切れ、ノッチや画面端との重なりがないこと。
- ディスプレイ仕様の根拠: [Apple公式仕様](https://support.apple.com/en-am/122209)。

初回リリースではこの実機合格を最優先する。外付け16:9モニターと将来のiOS／Androidは同じデータを使える設計にするが、初回版の合格を妨げない範囲で対応する。

## レイアウト基準

- 共通UIの論理基準解像度は `1280×720`。
- `CanvasScaler` は `Scale With Screen Size`を使う。MacBook基準実機では2倍相当の密度を前提とする。
- 背景は画面全体へ比率を保って拡大し、余白を出さない。縦横比が異なる場合にトリミングするのは背景の端だけとする。
- HUD、文章、選択肢、保存・戻るなどの操作要素は `Screen.safeArea` 内の共通ルートに置く。さらに論理解像度上で24px以上を内側余白とする。
- 人物の顔、名前欄、本文、決定ボタンは16:9の中央領域に収める。MacBookの縦長画面で増える領域は背景と装飾に使う。
- ラスターUIは原寸2倍で作成し、伸縮する枠は9-slice化する。文字を画像へ焼き込まない。
- 本文の基準サイズは論理22px以上、操作ボタンは論理48px以上の高さを保つ。小さなHUDでも18px未満を常用しない。

## 素材種別の制作仕様

### 背景

- 新規本番素材は `2560×1664px`以上。基準実機を1枚で覆える寸法で作る。
- 16:9表示では上下が一部切れる前提とし、人物、店名、道路の分岐、物語上の小道具を上下112pxの端に置かない。
- 文字、選択肢、操作説明を背景へ焼き込まない。
- 不透明素材の受け渡しはPNGを基本とする。写真系の容量が問題になる場合だけ高品質JPEGを使う。

### 立ち絵

- 企画書の掲載画像をキャラクターデザインの正本とする。顔、髪型、目の色、体格、年齢感、絵柄など「本人だと識別できる外見特徴」を独自に再解釈しない。
- 衣装は固定しない。レース、練習、自転車屋、学校、私服、デート、季節イベントなど、シーンと物語に合わせた変更を認める。同じ人物に見えること、シーン内で衣装が不連続に変わらないことを受け入れ条件とする。
- 新規本番マスターは高さ2304px以上を推奨する。使用時の表示寸法に対して少なくとも1.25倍のピクセル密度を持たせる。
- 透過PNG、sRGB、同一キャラクターは全差分で同じ画布サイズ・立ち位置・足元・ピボットを使う。表情切り替えで人物が跳ねないようにする。
- 標準配置は `{CharacterId}/{OutfitId}/{ExpressionId}`。基本表情は `neutral`。表情は `smile / strict / troubled`など少数の共通語彙を使い、シナリオごとの類似差分を増やさない。既存素材用に旧 `{CharacterId}_{ExpressionId}` も当面読み込む。
- 衣装差分は `OutfitId`（例: `cycling / casual / shop / school / date / seasonal`）で分離済み。表情IDに衣装名を混ぜない。
- 企画書から抽出した自転車屋の娘の1024×1536 JPEGは、試作とデザイン参照に使用可。新規本番素材の解像度目標は上記に従う。

### イベントCG

- `2560×1664px`以上。全面表示時にMacBook基準実機のネイティブピクセルを満たす。
- 主役の顔と重要な動作は中央の16:9安全領域に収める。台詞・選択肢・心情説明はCGへ焼き込まない。

### UI・アイコン

- 実寸表示の2倍で制作する。例: 64px表示のアイコンは128px原寸。
- 透過PNGを使い、大きく伸縮するパネルとボタンは9-slice前提で余白とborderを固定する。
- 文字と数値はTextMeshProで描画し、画像内に含めない。

### 音

- 制作マスターはWAV、48kHz。BGMはループ点を明記し、SEは前後の無音を必要最小限にする。
- Unity側の圧縮・ロード方式は素材の用途ごとに決める。BGMと長い環境音はStreaming、短いSEはDecompress On Loadを初期候補とする。

## 色とUnityインポート

- 素材の標準カラースペースはsRGB。MacBookのP3表示だけに合わせず、将来の外部モニターとスマホでも極端に色が変わらないことを優先する。
- 立ち絵・UI: Sprite / Single、Mip Map無効、Wrap Mode Clamp、Filter Mode Bilinear。
- 背景・CG: Texture Max Size 4096を上限の初期値とし、macOS実機の画質を見て圧縮形式を決める。元データ自体を小さく潰して調整しない。
- 一つの表情差分だけ寸法や設定が異なる状態を禁止し、キャラクター単位で設定をそろえる。

## 受け入れチェック

1. 企画書と比較し、キャラクターの顔・髪型・瞳・体格・年齢感・絵柄が一致している。衣装はそのシーンに合い、前後のイベントと連続している。
2. `2560×1664`フルスクリーンで原寸不足によるぼけが見えない。
3. `2560×1664`、`1920×1200`、`1920×1080`、`1280×720`で縦横比を保ち、操作要素と重要な人物部分が見切れない。
4. 全ボタンが画面端とセーフエリアの内側にあり、文章が欠けず、日本語フォントの欠落がない。
5. Unity上の表示確認とmacOS Playerのフルスクリーンスクリーンショットを残す。Editor表示だけで合格にしない。

## 現在の実装と差分

- ビルド対象の `InitScene`、`MainGameScene`、共通ローディング表示 `StandardUIManager` は1280×720と `Expand` へ統一済み。旧 `Scenario` は1920×1080のままだがビルド対象外であり、旧経路整理時に削除または更新する。
- macOS Playerはネイティブ解像度とRetina表示が有効。フルスクリーンウィンドウを初期基準とする。
- `MainGameScene` の一部に18px未満の文字がある。最終UI調整で基準以上へ修正する。
- BackgroundIdから背景Spriteを解決し、素材がなければ試作背景へ戻す処理を実装済み。短期ルートの背景画像自体は未制作。
- `Screen.safeArea` を反映する共通ルートは未実装。UIの構造整理時に整備する。
- 自転車屋の娘の現行立ち絵は企画書から抽出した正本デザインだが、透過ではない。本番用の透過原画が得られるまではデザイン確認用とする。
- Project Settingsの初期ウィンドウサイズは1024×768、ウィンドウリサイズ無効。フルスクリーン合格後に、設定画面とウィンドウモードの完了条件を別途定める。

## 将来のスマホ版への留意

- 画面サイズ、セーフエリア、入力、圧縮形式、AssetBundleのプラットフォーム差は分離する。
- 初回macOS版は横画面を正式とする。将来も横画面を前提とし、縦画面専用のレイアウトはこの段階では作らない。
- 素材IDと原画は共通化し、必要になった時点でプラットフォーム別の圧縮と解像度バリアントをビルドする。
