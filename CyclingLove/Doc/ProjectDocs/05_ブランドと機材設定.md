- 現実ブランドを避けながら、ロードバイク文化の違いをゲーム性に落とし込む
- 性能差だけでなく、キャラクター性やルート相性にもつなげる

## 現在の実装

機材マスタの正本は `Assets/Resources/Content/BikeParts.json`。`Version` と `Parts` を持ち、各パーツは次の項目で管理する。

- `Id / Name / BrandId / Slot / Price`
- `Performance`: `Stiffness / Lightness / Comfort / Handling / Aerodynamics`
- `Tags`: starter、reliable、climbing、raceなどの検索・条件用ID

Slotは `frame / components / wheels` の3種に固定する。現在はフレーム3件、コンポーネント2件、ホイール3件の計8件。主人公の初期所持・装備は次の3点。

| Slot | PartId | 名称 |
| --- | --- | --- |
| frame | frame_musashi_touring_01 | 武蔵 ツーリング |
| components | components_takumi_reliable_01 | 匠工房 Standard |
| wheels | wheels_takumi_endurance_01 | 匠工房 Endurance |

`GamePlayerData` は `OwnedPartIds` と `EquippedBike` を保存する。装備IDは所持品に含まれ、マスタ上のSlotと装備先が一致する必要がある。旧形式（v1／v2）のセーブに項目がない場合は、空の所持・装備状態として補完し、v3へ移行する。装備が欠けたセーブは、読み込み時にRulesの初期所持・初期装備で補う（[30_実装齟齬一覧.md](30_実装齟齬一覧.md) C-1）。キャンペーン新規開始時はRulesの初期所持・装備をコピーする。

購入・装備変更サービスは実装済み。購入前に資金と重複所持を検査し、成功時だけ資金を消費して所持IDを追加する。装備変更は所持済みのパーツをマスタ上のSlotへ設定する。失敗時は資金・所持・装備・Revisionを変更しない。購入・装備・レースの直後には自動保存しない。結果は次の保存（手動保存または進行時の保存）で保持される。

5性能値の合算、愛車構成ごとの熟練度、主人公能力を含む脚質判定、候補パーツ交換時の5項目差分は実装済み。ショップUI、装備比較、レース予測・結果はMainGameSceneの自転車メニューへ接続済み。故障率・解放条件は次段階。5性能値はレースのスコア計算へ反映している（[27_レース計算仕様.md](27_レース計算仕様.md)）。
