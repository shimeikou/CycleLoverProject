# シーン設計案

この文書は、`行動選択フェイズ` と `紙芝居パート` を前提にした Unity のシーン責務案です。

## 結論

今の段階では、**フェイズごとにシーンを分けすぎない** 方が良い。

最初のおすすめはこれです。

- `InitScene`
  - タイトル
  - セーブ選択
  - 設定
- `MainGameScene`
  - 日付進行
  - 行動選択
  - 紙芝居
  - 日次まとめ
- 将来必要なら追加
  - `RaceScene`
  - `SpecialEventScene`

つまり、**行動選択フェイズと紙芝居パートは、最初は同じ MainGameScene 内で状態切り替えする** のが一番安全です。

## なぜ分けすぎない方がいいか

今のゲームの核は、

- 日付
- 時間帯
- スケジュール
- イベント解決
- 報酬反映

です。

ここでシーンを細かく分けると、

- 毎回の状態引き継ぎが増える
- デバッグが難しくなる
- UI と進行ロジックの責務が散る
- まだ固まっていない段階で作り直しコストが増える

ので、今は得より損が大きいです。

## 推奨する責務分け

## 1. InitScene

役割:

- タイトル表示
- New Game / Load / Config / Exit
- セッション初期化の入口

ここでやること:

- `GameSession.IsNewGame`
- `CurrentSaveSlot`
- `GameSession.InitConfig()`

ここでやらないこと:

- 本編の日付進行
- イベント解決
- ADV 表示本体

## 2. MainGameScene

役割:

- 本編のメインループ
- 行動選択フェイズ
- 紙芝居イベント
- 夜のまとめ

ここでは**シーン切り替え**ではなく**内部状態切り替え**で運用する。

想定フェイズ:

- `Boot`
- `ResolveSchedule`
- `ActionSelect`
- `Scenario`
- `DailySummary`
- `AdvanceTime`

## 3. RaceScene

これは最初は不要。

後から以下のどちらかで判断する。

- レースがテキスト寄りの簡易解決なら `MainGameScene` に残す
- レースが専用 UI、専用演出、専用カメラを持つなら `RaceScene` に分離する

## 4. SpecialEventScene

これも最初は不要。

ただし以下の条件が揃ったら分ける価値がある。

- 専用背景や演出が大量に必要
- 通常日課と UI 構造が大きく異なる
- 読み込みコストを分離したい

## MainGameScene 内の状態設計

`MainGameScene` は 1 シーンのまま、内部状態でフェイズを切り替える。

例えば:

```csharp
public enum MainGamePhase
{
    None,
    Boot,
    ResolveSchedule,
    ActionSelect,
    Scenario,
    DailySummary,
    AdvanceTime,
    Finished,
}
```

## MainGameScene 内の表示レイヤー

Scene を増やす代わりに、表示レイヤーを分ける。

- `BaseHUD`
  - 日付
  - ステータス
  - 所持金
- `ActionPanel`
  - 行動選択
- `ScenarioPanel`
  - 会話表示
  - 立ち絵
  - 名前欄
- `SummaryPanel`
  - 1 日の結果
- `DebugPanel`
  - 現在フェイズ
  - 現在イベント

このやり方なら、**紙芝居パートは別シーンではなく、ScenarioPanel を前面に出すだけ** で済む。

## 紙芝居パートを別シーンにしない理由

紙芝居イベントは本質的には、

- ある日付
- ある時間帯
- あるイベントID

に紐づいた本編進行です。

別シーンにすると、

- 今どの日付か
- どのイベント報酬を反映したか
- どこへ戻るか

を毎回持ち回る必要があり、今の段階だと過剰です。

なので、**ADV 表示は MainGameScene 内の 1 パネルとして扱う** のが良いです。

## フェイズ遷移の基本形

```text
MainGameScene
  Boot
    -> ResolveSchedule
    -> ActionSelect or Scenario
    -> DailySummary
    -> AdvanceTime
    -> ResolveSchedule
```

## 将来分けるべき境界

以下の境界は後で分けやすいようにしておく価値がある。

- 進行制御
- 画面表示
- シナリオ再生
- レース再生

つまり、**コードの責務は分けるが、Scene はまだ増やさない** のがポイント。

## 今の開発段階でのおすすめ

### 今やる

- `MainGameScene` 1つで回す
- 行動選択フェイズと紙芝居パートを内部状態で切り替える
- デバッグ表示で現在フェイズを見えるようにする

### まだやらない

- 行動選択用 Scene
- ADV 専用 Scene
- まとめ画面専用 Scene

## 実装イメージ

### Presenter

- MainGame 全体のフェイズ制御

### Model / Service

- スケジュール解決
- イベント解決
- 時間進行
- 報酬適用

### View

- どのパネルを表示するか
- 選択肢入力
- シナリオ表示

## まとめ

今の正解は、

- シーンは少なく
- フェイズは多く
- 責務はコードで分ける

です。

特にこのゲームでは、`行動選択` と `紙芝居` は**本編の連続した流れ**なので、まずは同一 Scene 内で回す設計が一番相性が良いです。
