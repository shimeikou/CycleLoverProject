# 実装向け論点整理

この文書は、PDF 企画書を現在の Unity プロジェクトへ落とし込む際に、特に確認したい点をまとめたものです。

## 1. ステータス名称の不一致

PDF では以下の差分がある。

- ハート vs タフネス
- チャーム vs エンパシー

現在のコードでは `PHYSICAL / HEART / SMART / CHARM / APPEAL` に近い前半の命名で設計が進みそうな雰囲気があるため、企画上の正式名称を決めたい。

## 2. 時間帯設計の整理

企画書には以下がある。

- 午前
- 午後
- 夜
- 週末・祝日イベント

現在の方針では `Morning / Afternoon / Evening / Special` を使うため、以下を決める必要がある。

- `Special` を何として扱うか
- 夜行動を選択式にするか、結果確認専用にするか
- 週末イベントが通常時間帯に割り込むのか、別フローなのか

## 3. 1 年進行の粒度

未確定のまま残っている点:

- 毎日フルに操作するのか
- 一部の日をスキップ可能にするのか
- シーズン目標の判定タイミング
- 祝日や固定イベントカレンダーの持ち方

## 4. ヒロイン解放条件

PDF では隠しヒロインが存在するが、条件の厳密仕様は未定。

必要そうな条件候補:

- 2 周目以降
- アピールしきい値
- レース実績
- 特定サブキャラとの接触
- 特定アプリや番組イベントの発生

## 5. 機材データの持ち方

実装前に決めたいこと:

- フレーム、コンポ、ホイールを個別マスタ化するか
- ブランド単位で共通補正を持たせるか
- パーツごとの故障率や耐久を入れるか
- キャラ専用機材を一般流通品と分けるか

## 6. レース解決方式

企画書から推測できる要素:

- プレイヤーステータス
- 愛車性能
- コース適性
- 天候
- 精神力
- 特殊イベント

まだ必要な設計:

- 完全自動判定か
- コマンド選択型か
- 簡易シミュレーションか

## 7. 地域活性化要素の扱い

物語全体には以下の要素が通底している。

- 地方移住
- 町おこし
- 地域の魅力再発見
- 人と人のつながり

このため、恋愛と育成だけでなく、全体進行を束ねるもう 1 本の軸が必要そう。

候補:

- 地域貢献度
- 知名度
- 観光発信度
- 狐の依頼達成数

## 8. 現在コードとの初期対応

現時点のコード構造と相性が良さそうな分割は以下。

- `GameDate`: 日付と時間帯
- `ScheduleDay`: 1 日のイベント定義
- `GameEvent`: 特定時間帯イベント
- `ScenarioScriptData`: 会話や演出
- `GamePlayerData`: プレイヤー状態
- `SoTotalSchedule`: 年間または月間スケジュール参照

## 9. 次に仕様化すると良い順番

1. ステータス正式名称の確定
2. 1 日の行動仕様の固定
3. ヒロイン別の解放条件と必要能力の確定
4. 愛車パーツのデータテーブル設計
5. レース判定ロジックの簡易版定義
6. サブキャラと特殊依頼の統合設計

## PDF 原本の対応範囲

- 全体横断
