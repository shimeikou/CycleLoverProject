# 外部データの編集ガイド

更新日: 2026-10-16

## 編集するファイル

現在の実行対象の正本は `Assets/Resources/Content/` の `Annual` 系JSON。ゲーム開始時に読み込み、定義を検証してからコピーして使用する。`BikeshopShort` 系と `Prototype` 系は10日版・3日版の回帰テスト用に残す。

| ファイル | 編集する内容 |
| --- | --- |
| PrototypeCampaign.json | キャンペーンID・シナリオID・内容バージョン・開始日・終了本文・選択画面の説明・以下3ファイルの参照キー |
| PrototypeRules.json | 主人公の初期値、体力上限、翌朝の回復量 |
| PrototypeActions.json | 行動ID・表示名・コスト・行動結果の本文・効果 |
| PrototypeDays.json | 日ごとのID・見出し・午前本文と効果・午後導入本文・行動候補・午後共通効果・日次追記 |
| BikeshopShortCampaign.json | 10日短期ルートのマニフェスト。実ゲームが読み込む対象 |
| BikeshopShortActions.json | 短期ルートの通常行動、固定イベント、会話選択肢、条件、報酬 |
| BikeshopShortDays.json | 2026年4月1日〜10日の本文、行動候補、日次効果 |
| BikeParts.json | フレーム・コンポーネント・ホイールのID、ブランド、価格、5性能値、タグ |
| Races.json | コース種別、距離、目標スコア、能力・機材・熟練度の係数、成功報酬 |
| AnnualCalendar.json | 年間の開始・終了日、四季、週末休日、日付例外、季節目標、年末結末 |
| AnnualCampaign.json | 現在の年間実行版マニフェスト。基本行動と年間ルート固有行動、日程、カレンダーを参照 |
| AnnualBikeshopActions.json | 自転車屋の娘の年間イベント本文、選択肢、効果 |
| AnnualCafeActions.json | カフェのマスターの年間イベント本文、選択肢、効果 |
| AnnualCousinActions.json | 従妹の年間イベント本文、選択肢、効果 |
| AnnualAnnouncerActions.json | 周回解放される女子アナの年間イベント本文、選択肢、効果 |
| AnnualOnlineRivalActions.json | 条件付きで解放されるネットのライバルの年間イベント本文、選択肢、効果 |
| AnnualRegionalActions.json | 祖母のヒント、ルート別の地域支援、狐の依頼の本文と報酬 |
| AnnualRouteActions.json | 年間開始時の攻略ルート選択肢と専用ルートフラグ |
| AnnualSchedule.json | 平日・休日・季節締切・年末の1日テンプレート、適用優先ルール、条件付きイベント |

これは「コードから独立した編集データ」であり、配布ビルドにはTextAssetとして同梱される。配布後に横置きJSONを差し替える機能、実行中のホットリロード、表計算からの取込はまだ実装していない。読込方法はCampaignContentLoaderに閉じ込めてある。

機材は `EquipmentContentLoader` から読み込む。キャンペーン本文と別カタログにし、購入・装備・レース側が同じPartIdを参照する。Slotは `frame / components / wheels` のみ。ID重複、負の価格・性能、未知Slot、重複タグ、所持していない装備、装備先とSlotの不一致を拒否する。

レースは `RaceContentLoader` から読み込む。係数は0以上の整数とし、少なくとも1項目を正にする。初版は乱数なしで、同じ状態なら同じScoreと成否を返す。詳しい式と現行の基準値は [27_レース計算仕様.md](27_レース計算仕様.md)。

## 初期パラメータと回復

`PrototypeRules.json` の `InitialPlayer` には名前、年齢、開始場所、資金、体力、5能力値がある。新規開始時の正本はこのデータ。保存データをロードした場合は初期値を上書きしない。

- `MaxStamina`: 体力上限。正の整数。
- `OvernightRecovery`: 翌朝の体力回復。0以上。
- 初期体力は0以上かつ上限以下。資金・能力値は0以上。
- 回復処理・セーブの内容検証・HUDの上限表示は同じ上限値を使う。
- 保存ファイル自体の構造検証は体力100を固定しない。対応するキャンペーンへ復帰するときに、そのキャンペーンの上限を検証する。

GamePlayerDataに残る初期値は旧コード／旧テストとの互換用。通常の新規開始ではRulesの値が必ず適用されるため、調整目的でGamePlayerDataを変更しない。

## 行動と日程を追加する

1. Actions配列へ一意な `Id` と `Name`、`StaminaCost`、`MoneyCost`、`Pages`、`Effects` を追加する。
2. 対象日の `ActionIds` にそのIDを追加する。並び順が候補の表示順になる。4件以上はページ送りで表示する。
3. 日を増やす場合はDays配列へ追加する。各日の `Id` は一意にし、配列順で開始日から1日ずつ進む。日付・月の繰上げは進行処理が行う。
4. 各日には体力・資金がゼロでも選べる行動を必ず1件含める。参照先の欠損、重複ID、空本文、不正な値は開始前にエラーにする。

Effectsは `Money / Physical / Toughness / Smart / Empathy / Appeal / Stamina / Affection / BikeMastery` の加算値と、`RouteStep / HeroineId / RouteFlag` の記録を扱う。`Affection` と `RouteStep` には `HeroineId` が必須。好感度と愛車熟練度は100を上限とし、RouteStepは現在値を後退させない。BikeMasteryは実行時のフレーム・コンポーネント・ホイール構成に加算する。数値報酬は0以上、支出・消費は行動のCostへ分ける。

会話選択肢は行動へ `ChoicePrompt` と `Choices` を追加する。各Choiceには一意な `Id`、表示用の `Label / Description`、選択後の `Pages / Effects` を持たせる。条件付き選択肢を含む場合も、進行不能を避けるため `Conditions` のない選択肢を最低1件含める。

ConditionsのTypeは `money / physical / toughness / smart / empathy / appeal / stamina / affection / route_step / heroine_met / route_flag / event_cleared / race_attempted / race_succeeded`。数値条件は現在値がValue以上で成立する。ヒロイン条件とフラグ・既読・レース条件は対象の `Id` が必須。レース条件のIdはRaceId。条件未達の選択肢は画面へ残るが選択できず、無条件の代替イベントから進行できる。

年間の条件付きイベントは `AnnualSchedule.json` の `ConditionalEvents` へ追加する。`Id / TemplateId / Priority / HolidayMode` を必須とし、必要に応じて開始・終了日、`SeasonId`、`SpecialSlotId`、`Conditions`、`Repeatable` を指定する。期間を使う場合は開始日と終了日の6項目をすべて指定する。同日に複数成立した場合はPriorityが大きいものを選び、同値はID順で決定する。`Repeatable` の既定値はfalseで、既読後は再発しない。イベント本文はTemplatesのDayを参照し、起動時の365日展開にはプレイヤー状態を焼き込まない。

年間ルート固有の行動は、マニフェストの `AdditionalActionsResources` にカタログを追加して通常行動と結合する。現在は `AnnualRouteActions.json` と通常3名・隠し2名の年間Actionカタログを参照し、10日短期版の `BikeshopShortActions.json` を変更せず年間イベントを分離している。結合後のAction IDは全カタログを通して一意でなければならない。

演出位置はCampaignの `ScenarioId` と、Day／Action／Choiceの `NodeId` で指定する。未指定のDayは日IDからNodeIdを補完する。午後の表示指定はChoice、Action、Dayの順に優先する。

背景は `BackgroundId`、人物は `CharacterId / OutfitId / ExpressionId` で指定する。背景は `Assets/Resources/Images/Backgrounds/{BackgroundId}`、人物の標準配置は `Assets/Resources/Images/Characters/{CharacterId}/{OutfitId}/{ExpressionId}`。移行中は平坦名と旧 `{CharacterId}_{ExpressionId}` も読める。表情素材がなければneutralへ戻す。現在登録済みの `hero_bikeshop_neutral` は、企画書14ページの埋め込み元画像を抽出したJPEG。黒のショートボブ、青い瞳、体格、年齢感と絵柄を正本とする。衣装はシーンに合わせて変更できる。短期ルートのIDと不足素材は [26_短期ルート素材台帳.md](26_短期ルート素材台帳.md) で管理する。

Pagesの最後に表示する数値効果は定義から自動生成する。本文へ「資金+500」等の効果表示を重ねて書かない。行動説明、本文末尾、実際の適用値がずれないようにする。物語の台詞として金額を記載する場合は、調整時に文章も確認する。

## 保存と内容のバージョン

ファイルの分割だけではゲーム内容の版を変えない。3日回帰版の `prototype` と10日実行版の `bikeshop_short` は別のCampaignIdを持ち、それぞれVersion 1。保存スロットも分離している。

本番で既存保存がある状態で日程・ページ・効果・上限を変更する場合は `Version` を更新する。現時点では保存と内容の版が異なると復帰を拒否する。自動移行やNodeIdによる本文位置の復元は今後の作業。IDを後から変更すると完了済み記録との対応が崩れるため、安易にリネームしない。

セーブファイル自身の `FlowVersion` は3。v1の保存は出会い済みヒロインの進行情報を補完し、v1／v2の両方へ機材・レース・季節目標・年間結末の保存欄を補って読込時に自動移行する。年間結末は未確定状態を明示し、確定後だけID・成否・判定日を保存する。未知の形式は拒否する。`ContentVersion` は物語内容との互換性、`FlowVersion` はセーブ構造との互換性であり、同じ番号である必要はない。

## 検証結果と範囲

### ビルド前の自動検証

通常のPlayerビルド開始時に、実行時と同じCampaignContentLoader・定義検証を実行する。現在の対象は実行版 `Content/AnnualCampaign`、回帰用 `Content/BikeshopShortCampaign` と `Content/PrototypeCampaign`、各マニフェストが参照するRules／Actions／Days／Schedule、`Content/AnnualCalendar`、`Content/BikeParts`、`Content/Races`（`Assets/Scripts/Editor/CampaignBuildValidator.cs`）。Resources内の全JSONを自動走査する仕組みではない。

手動確認はUnityメニュー **Tools > Cycling Love > Validate Campaign Data**。正常時はConsoleに成功を表示し、不正時は原因を含むBuildFailedExceptionでビルドを中止する。ただしメッセージ先頭のキャンペーン名はどのファイルが失敗しても `[Content/BikeshopShortCampaign]` と表示されるため、原因文で対象を判断する。ファイル不足・空ファイル・JSON解析失敗・重複ID・行動参照の不足・不正パラメータなど、現行定義の制約を検証する。未定義フィールドの誤字をすべて検出する厳密なJSON Schema検証ではない。

Editor専用のGame.Editorアセンブリに配置し、ゲーム本体にUnityEditor依存を持ち込まない。テストの不正データはメモリ内に作り、制作中のJSONを書き換えない。

### 外部化時の検証記録
