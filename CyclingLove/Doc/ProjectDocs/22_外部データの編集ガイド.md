# 外部データの編集ガイド

更新日: 2026-10-21

## 編集するファイル

現在の実行対象の正本は `Assets/Resources/Content/` の `Annual` 系JSON。ゲーム開始時に読み込み、定義を検証してからコピーして使用する。`BikeshopShort` 系と `Prototype` 系は10日版・3日版の回帰テスト用に残す。

| ファイル | 編集する内容 |
| --- | --- |
| PrototypeCampaign.json | キャンペーンID・シナリオID・内容バージョン・開始日・終了本文・選択画面の説明・以下3ファイルの参照キー |
| PrototypeRules.json | 主人公の初期値、体力上限、翌朝の回復量 |
| PrototypeActions.json | 行動ID・表示名・コスト・行動結果の本文・効果 |
| PrototypeDays.json | 日ごとのID・見出し・午前本文と効果・午後導入本文・行動候補・午後共通効果・日次追記 |
| BikeshopShortCampaign.json | 10日短期ルートのマニフェスト。実ゲームが読み込む対象 |
| CommonActions.json | 年間版と10日回帰版が共有する基礎練習、町歩き、休息 |
| BikeshopShortActions.json | 10日回帰版だけの固定イベント、会話選択肢、条件、報酬 |
| BikeshopShortDays.json | 2026年4月1日〜10日の本文、行動候補、日次効果 |
| BikeParts.json | フレーム・コンポーネント・ホイールのID、ブランド、価格、5性能値、タグ |
| BikeVisuals.json | マイバイク3D表示用の部品ID、Slot、論理アドレス、フォールバック、配布パック |
| Races.json | コース種別、距離、目標スコア、能力・機材・熟練度の係数、成功報酬 |
| AnnualCalendar.json | 年間の開始・終了日、四季、週末休日、日付例外、季節目標、年末結末 |
| AnnualCampaign.json | 現在の年間実行版マニフェスト。基本行動と年間ルート固有行動、日程、カレンダーを参照 |
| AnnualBikeshopActions.json | 自転車屋の娘の年間イベント本文、選択肢、効果 |
| AnnualCafeActions.json | カフェのマスターの年間イベント本文、選択肢、効果 |
| AnnualCousinActions.json | 従妹の年間イベント本文、選択肢、効果 |
| AnnualAnnouncerActions.json | 周回解放される女子アナの年間イベント本文、選択肢、効果 |
| AnnualOnlineRivalActions.json | 条件付きで解放されるネットのライバルの年間イベント本文、選択肢、効果 |

| AnnualRouteActions.json | 年間開始時の攻略ルート選択肢と専用ルートフラグ |
| AnnualSchedule.json | 平日・休日・季節締切・年末の1日テンプレート、適用優先ルール、条件付きイベント |

これは「コードから独立した編集データ」であり、配布ビルドにはTextAssetとして同梱される。配布後に横置きJSONを差し替える機能、実行中のホットリロード、表計算からの取込はまだ実装していない。読込方法はCampaignContentLoaderに閉じ込めてある。

機材は `EquipmentContentLoader` から読み込む。キャンペーン本文と別カタログにし、購入・装備・レース側が同じPartIdを参照する。Slotは `frame / components / wheels` のみ。ID重複、負の価格・性能、未知Slot、重複タグ、所持していない装備、装備先とSlotの不一致を拒否する。

3D表示は `BikeVisualContentLoader` から読み込む。`BikeVisuals.json` の全PartIdは `BikeParts.json` に存在し、Slotが一致し、機材8件すべてに表示項目がなければならない。AddressとPackIdはセーブへ保存しない。モデルの更新・配布方式が変わってもPartIdを維持する。詳細は [36_マイバイク3Dビュー仕様.md](36_マイバイク3Dビュー仕様.md)。

レースは `RaceContentLoader` から読み込む。係数は0以上の整数とし、少なくとも1項目を正にする。初版は乱数なしで、同じ状態なら同じScoreと成否を返す。詳しい式と現行の基準値は [27_レース計算仕様.md](27_レース計算仕様.md)。

## 初期パラメータと回復

`PrototypeRules.json` の `InitialPlayer` には名前、年齢、開始場所、資金、体力、5能力値がある。新規開始時の正本はこのデータ。保存データをロードした場合は初期値を上書きしない。

- `MaxStamina`: 体力上限。正の整数。
- `OvernightRecovery`: 翌朝の体力回復。0以上。
- 初期体力は0以上かつ上限以下。資金・能力値は0以上。
- 回復処理・セーブの内容検証・HUDの上限表示は同じ上限値を使う。
- 保存ファイル自体の構造検証は体力100を固定しない。対応するキャンペーンへ復帰するときに、そのキャンペーンの上限を検証する。

GamePlayerDataに残る初期値は旧コード／旧テストとの互換用。通常の新規開始ではRulesの値が必ず適用されるため、調整目的でGamePlayerDataを変更しない。

## 行動と日程を追加する

1. Actions配列へ一意な `Id` と `Name`、`StaminaCost`、`MoneyCost`、`Pages`、`Effects` を追加する。
2. 対象日の `ActionIds` にそのIDを追加する。並び順が候補の表示順になる。4件以上はページ送りで表示する。
3. 日を増やす場合はDays配列へ追加する。各日の `Id` は一意にし、配列順で開始日から1日ずつ進む。日付・月の繰上げは進行処理が行う。
4. 各日には体力・資金がゼロでも選べる行動を必ず1件含める。参照先の欠損、重複ID、空本文、不正な値は開始前にエラーにする。

Effectsは `Money / Physical / Toughness / Smart / Empathy / Appeal / Stamina / Affection / BikeMastery` の加算値と、`RouteStep / HeroineId / RouteFlag` の記録を扱う。`Affection` と `RouteStep` には `HeroineId` が必須。好感度と愛車熟練度は100を上限とし、RouteStepは現在値を後退させない。BikeMasteryは実行時のフレーム・コンポーネント・ホイール構成に加算する。数値報酬は0以上、支出・消費は行動のCostへ分ける。

会話選択肢は行動へ `ChoicePrompt` と `Choices` を追加する。各Choiceには一意な `Id`、表示用の `Label / Description`、選択後の `Pages / Effects` を持たせる。条件付き選択肢を含む場合も、進行不能を避けるため `Conditions` のない選択肢を最低1件含める。

結果判定だけにChoicesを使い、プレイヤーへ選択画面を出さない行動は `AutoSelectChoice: true` を指定する。この場合、JSONの並び順で最初に条件を満たすChoiceを自動採用する。優先したい結果を先に置き、最後に無条件の代替結果を置く。判定条件と結果本文・効果を同じChoiceへまとめられるため、コードへ個別ルート判定を追加しない。

ConditionsのTypeは `money / physical / toughness / smart / empathy / appeal / stamina / affection / route_step / heroine_met / route_flag / event_cleared / race_attempted / race_succeeded`。数値条件は現在値がValue以上で成立する。`"Not": true` を付けると判定を反転し、数値条件は「Value未満」、フラグ・既読・レース等は「無い」で成立する。否定したRouteFlag／RouteStep条件は生成元の検査対象から外す。ヒロイン条件とフラグ・既読・レース条件は対象の `Id` が必須。レース条件のIdはRaceId。条件未達の選択肢は画面へ残るが選択できず、無条件の代替イベントから進行できる。

年間の条件付きイベントは `AnnualSchedule.json` の `ConditionalEvents` へ追加する。`Id / TemplateId / Priority / HolidayMode` を必須とし、必要に応じて開始・終了日、`SeasonId`、`SpecialSlotId`、`DaysOfWeek`、`Conditions`、`Repeatable` を指定する。`DaysOfWeek` は `["Monday", "Friday"]` のような英語の曜日名（大文字小文字は不問）で、DayRuleにも指定できる。期間を使う場合は開始日と終了日の6項目をすべて指定する。同日に複数成立した場合はPriorityが大きいものを選び、同値はID順で決定する。`Repeatable` の既定値はfalseで、既読後は再発しない。イベント本文はTemplatesのDayを参照し、起動時の365日展開にはプレイヤー状態を焼き込まない。

DayRuleとConditionalEventは、日付・季節・休日区分・特別枠をすべて同時に満たす日が年間カレンダー内に最低1日必要。例えば「土曜日の1日だけ」を期間にしながら `HolidayMode: workday` を指定すると、ビルド前検証で到達不能として拒否する。条件が要求するRouteFlagは、いずれかのAction／Choice、季節目標、年末結果、レース結果に生成元が必要。RouteStep条件も、同じHeroineIdに対してその段階以上を設定する効果が必要。

共通の日常行動は `CommonActions.json` に置く。10日回帰版の固定イベントは `BikeshopShortActions.json`、年間ルート固有の行動は `AnnualRouteActions.json` と通常3名・隠し2名の年間Actionカタログへ分離する。各マニフェストの `AdditionalActionsResources` で必要なカタログだけを結合し、結合後のAction IDは全カタログを通して一意にする。年間版は短期版カタログへ依存しない。

演出位置はCampaignの `ScenarioId` と、Day／Action／Choiceの `NodeId` で指定する。未指定のDayは日IDからNodeIdを補完する。午後の実行ノードはDay、Action、ChoiceのNodeIdを `::` で連結し、同じ行動を別の日に選んでも一意になる。行動選択画面と午後導入ページはDayの表示素材を使い、行動本文へ入った後はChoice、Action、Dayの順に優先する。

背景は `BackgroundId`、人物は `CharacterId / OutfitId / ExpressionId` で指定する。背景は `Assets/Resources/Images/Backgrounds/{BackgroundId}`、人物の標準配置は `Assets/Resources/Images/Characters/{CharacterId}/{OutfitId}/{ExpressionId}`。移行中は平坦名と旧 `{CharacterId}_{ExpressionId}` も読める。表情素材がなければneutralへ戻す。現在登録済みの `hero_bikeshop_neutral` は、企画書14ページの埋め込み元画像を抽出したJPEG。黒のショートボブ、青い瞳、体格、年齢感と絵柄を正本とする。衣装はシーンに合わせて変更できる。短期ルートのIDと不足素材は [26_短期ルート素材台帳.md](26_短期ルート素材台帳.md) で管理する。

Pagesの最後に表示する数値効果は定義から自動生成する。本文へ「資金+500」等の効果表示を重ねて書かない。行動説明、本文末尾、実際の適用値がずれないようにする。物語の台詞として金額を記載する場合は、調整時に文章も確認する。

## 保存と内容のバージョン

ファイルの分割だけではゲーム内容の版を変えない。3日回帰版の `prototype` と10日実行版の `bikeshop_short` は別のCampaignIdを持ち、それぞれVersion 1。保存スロットも分離している。

セーブ形式v6はScenarioId／NodeId／PageIdを保持する。PageIdは本文から決定的に生成されるため、同じノード内へ文章を挿入・並べ替えても保存時の文章を再検索する。保存した文章自体を変更・削除した場合やノードIDが一致しない場合は、そのノードの先頭へ戻る。復帰だけでは効果を適用せず、既読イベントキーで二重報酬を防ぐ。

誤字修正や本文の追加・並べ替えだけで、日程・条件・効果・ノードの意味を変えない場合は同じ `Version` のまま更新できる。日程、選択条件、効果、上限、NodeIdの意味を変えて既存保存との互換性がなくなる場合は `Version` を更新する。現時点では異なるContentVersion間の自動移行は行わず、復帰を拒否する。IDを後から変更すると完了済み記録との対応が崩れるため、安易にリネームしない。

セーブファイル自身の `FlowVersion` は6。v1〜v5は不足する進行情報、機材、レース、季節目標、年間結末、地域進行、シナリオチェックポイントを補って読込時に自動移行する。v5以前で会話中だった保存は従来のページ番号を一度だけ引き継ぎ、その後ScenarioId／NodeId／PageIdを保存する。年間結末は未確定状態を明示し、確定後だけID・成否・判定日を保存する。未知の形式は拒否する。`ContentVersion` は物語内容との互換性、`FlowVersion` はセーブ構造との互換性であり、同じ番号である必要はない。

## 検証結果と範囲

### ビルド前の自動検証

通常のPlayerビルド開始時に、実行時と同じCampaignContentLoader・定義検証を実行する。現在の対象は実行版 `Content/AnnualCampaign`、回帰用 `Content/BikeshopShortCampaign` と `Content/PrototypeCampaign`、各マニフェストが参照するRules／Actions／Days／Schedule、`Content/AnnualCalendar`、`Content/BikeParts`、`Content/BikeVisuals`、`Content/Races`（`Assets/Scripts/Editor/CampaignBuildValidator.cs`）。年間版はカレンダー上の成立日、RouteFlag生成元、RouteStep最大到達値も相互検査する。背景と人物差分は3キャンペーンの参照を収集し、現在のResources解決経路で不足するものを一覧警告する。素材制作中のビルドは止めず、代替表示を使う。Resources内の全JSONを自動走査する仕組みではない。

手動確認はUnityメニュー **Tools > Cycling Love > Validate Campaign Data**。正常時はConsoleに成功を表示し、不正時は原因を含むBuildFailedExceptionでビルドを中止する。メッセージの角括弧には失敗した検証対象（試作、短期回帰、年間版、機材、3D表示、レース、カレンダー）を表示し、原因文には不足・空・解析失敗した参照先のResourceキーも表示する。ファイル不足・空ファイル・JSON解析失敗・重複ID・行動参照の不足・不正パラメータなど、現行定義の制約を検証する。未定義フィールドの誤字をすべて検出する厳密なJSON Schema検証ではない。

Editor専用のGame.Editorアセンブリに配置し、ゲーム本体にUnityEditor依存を持ち込まない。テストの不正データはメモリ内に作り、制作中のJSONを書き換えない。

### 外部化時の検証記録

2026-10-17、通常3名と隠し2名の各8イベント、四季目標、ヒロイン別告白結末、周回記録と解放判定、地域イベントと狐の依頼、年間調整画面を追加後、プロジェクトのEditModeテスト82ケース成功、コンパイル失敗なし。

条件境界の確認は `Tools/Cycling Love/Campaign Tuning` を使う。日付、能力、地域進行、ID一覧、ヒロイン進行を仮入力すると、当日の成立イベントと優先採用、四季目標、年末結末を表示する。この画面は実セーブを読み書きしない。

- 初期値変更、体力上限160、休息と翌朝回復、JSON保存形式での復帰確認。
- 定義変更後の説明・本文末尾と実際の効果の一致。
- 不正な初期値・上限・不足ファイルの拒否。
- ヒロイン別の好感度・RouteStepの保存復帰、v1保存の補完、重複ID・不正値の拒否。
- 会話選択肢、能力・好感度・既読フラグ等の条件、無条件代替肢、選択報酬の一度だけの適用。
- 10日短期ルートの成功・条件未達を完走し、各進行地点のJSON保存復元後も本文と条件判定が一致。
- 季節目標と年末結末が締切前に確定せず、締切後は結果フラグ・判定日を一度だけ保存し、JSON復元後も保持。
- 平日・休日の既定テンプレートと特別枠の優先ルールから、重複IDのない2026年4月1日〜2027年3月31日の365日を生成。
- 既存の3日間完走、各進行地点の保存復帰、実ファイル保存、連打防止などの回帰テスト。

日次イベント、会話選択肢、条件分岐、条件付き年間イベント、ScenarioId／NodeId、背景・人物・衣装・表情ID、機材、レース、年間カレンダー、音29 IDと場面ルールは外部化済み。周回記録はシステム保存の `ProfileProgress` で管理する。音は `AudioCatalog.json` のID、種類、Address、PackId、AssetPath、ループ、音量と、優先度付き場面ルールを編集する。WAV配置後はUnityメニュー **Tools > Cycling Love > Audio > Sync Present Assets to Addressables** を実行する。現在は「午前本文→午後行動→任意の会話選択→日次結果」と各場面の画像・音指定をJSON編集で追加できる。
